# 보고서 템플릿 — 하루 한 파일, 이어 붙이기

## 파일 규칙 (SKILL.md 대원칙 B)

**`logs/dailycheck/<YYYY-MM-DD>_report.md` 한 파일뿐이다.**

| 국면 | 하는 일 | 쓰는 절 |
|---|---|---|
| 장전 `pre` | 파일을 **만든다** | 헤더 · `§0` · `제1부 장전` |
| 장중 `intra` | 끝에 **이어 붙인다** | `제2부 장중` (+ `§0` 갱신 블록) |
| 장후 `post` | 이어 붙이고 **하루를 닫는다** | `제3부 장후` · `종합` · `제4·5부` · `사용자 조치` |

- **`_pre_report.md` / `_intra_report.md` / `_post_report.md` 는 만들지 않는다.**
- **앞 국면 절의 본문을 고치거나 지우지 않는다.** 정정은 뒤 국면 절에서 하고, 앞 절에는
  `> ↩️ 12:30 정정 — 2-3 참조` 한 줄만 붙인다. 왜 그때 그렇게 판단했는지가 남아야 한다.
- 같은 국면을 하루에 두 번 점검하면 새 파일이 아니라 절을 더 붙인다 —
  `## 제2부-B. 장중 재점검 (14:10)`. (2026-08-14 F-12의 요구를 이 방식으로 더 강하게 지킨다.)
- `§0`만은 예외적으로 **갱신 블록을 아래에 덧붙이는 방식**으로 최신화한다(지우지 않고 쌓는다).

아래 구조를 그대로 쓰되, 해당 없는 절은 "해당 없음"으로 남기고 삭제하지 않는다 — 빠진 절과 없는 항목은 다르다.

## 작성 시 주의

**증거 규율 (종전대로 — 하나도 완화되지 않았다)**

- **인용 없는 이상점은 쓰지 않는다.** 로그 시각과 파일명이 반드시 붙는다.
- **"개선한다"류 동사를 쓰지 않는다.** 어느 파일 어느 함수에서 무엇을 어떻게 바꾸는지 쓴다.
- **재발 항목은 무조건 P0 맨 위로.** 원래 고쳤다는 커밋 sha까지 찾아 붙인다.
- **판정 보류를 부끄러워하지 않는다.** 틀린 확정보다 정직한 보류가 낫다. 단, 무엇을 보면 판정되는지는 반드시 쓴다.
- **전일 보고서가 있으면 델타를 쓴다.** `logs/dailycheck/<전 거래일>_report.md` 를 찾아 비교한다.

**읽기 규율 (대원칙 A)**

- **쉽게 쓴다는 것은 줄인다는 뜻이 아니다.** 순서와 표현만 바꾼다. 증거를 덜어냈으면 위반이다.
- `§0`에 약어·태그명·파일경로·조항번호가 하나라도 있으면 다시 쓴다.
- 약어는 첫 등장에서 한 번 풀어쓴다. `R11(장중 배포 금지 규칙)` `p90(100번 중 90번이 이 값 이하)`.
- 맨숫자 금지. `925ms(완성봉 유예 500ms의 1.85배)` · `-320,000원(자본 대비 -0.64%)` ·
  `MDD 4.1%(peak 대비 · 자본 대비 2.2%)` · `3계약(선물 포지션)`.
- `**영향**`(평문 한 문장)과 `**영향(기술)**` 을 **둘 다** 쓴다. 하나만 쓰면 미완성이다.
- 사용자 조치는 맨 끝 한 절에. 각 항목에 **걸리는 시간**과 **안 하면 생기는 일**.

**이어 붙이기 규율 (대원칙 B)**

- 앞 국면 절 본문은 **읽기 전용**이다. 정정은 뒤에서, 앞에는 포인터 한 줄.
- 앞 국면 항목을 전부 처분하기 전에는 신규 이상점을 쓰지 않는다.
- 이상점 번호는 하루 안에서 이어지고, **지속 항목에 새 번호를 주지 않는다.**
- 장후는 **이 파일 하나만 읽고 그날이 전부 재구성되는지** 스스로 물은 뒤 낸다.
