## 2.4 Aggregator — 국면 가중치가 게이트 도달 가능성을 정한다

```
S = Σ_h [ w(regime, h) × (P_h(+1) − P_h(−1)) × meta_h × (1 − u_h) × f_h ]
```

- `meta_h` = meta_passed ? 1 : 0 → **현재 항상 1**
- `u_h` = clip(ens_std / 0.5, 0, 1) → 08-21 실측 0.001~0.057 (거의 감쇠 없음)
- `f_h` = 신선도, `as_of == valid_until`이라 **항상 1.0**

Expert가 30m 하나뿐이라 `S = w(regime, 30m) × dir × (1 − u)`로 축약된다. 그래서
**국면이 게이트 통과 가능성을 그대로 결정한다** — `w`가 국면마다 다르기 때문이다:

| 국면 | w(30m) | \|S\| ≥ 0.20에 필요한 \|dir\| | 판정 |
|---|---|---|---|
| TREND_UP / TREND_DOWN | 1.5 | **0.134** | 도달 가능 |
| HIGH_VOL | 0.8 | 0.251 | 어렵다 |
| RANGE | 0.4 | **0.502** | 사실상 불가 (한쪽 확률이 다른 쪽보다 0.5 넘게 우세해야 함) |
| EVENT / UNKNOWN | 0.5 | 0.401 | 규칙 ②가 먼저 접는다 |

**RANGE 국면 구간에는 30m 단독 배선으로 진입이 나올 수 없다.** 08-21은 14사이클 중 RANGE가
6, TREND_DOWN 5, HIGH_VOL 3이었다. 이 비대칭은 08-16판에 없던 계량이다.

## 2.6 레이블 기하 — 08-16판의 주장을 정정한다

전부에서 **비용 강등 규칙이 0건**이며, 30m flat의 99.6%가 왕복 비용의 100배 넘게 움직인

## 3.3 Net Expected Return

```
edge       = clip(2 × confidence − 1, 0, 1)
Net ER(틱) = edge × ATR(M1,14) − 왕복비용
```

08-21 15:30 실측: `confidence 0.4873` → `edge 0.0` · `ATR 48.93틱` · `비용 1.6232틱`
→ **Net ER = −1.6232틱**.

⚠️ 명시적 근사다. 크기(magnitude) 예측 모델이 없어 ATR을 기대이동폭 대용으로 쓴다.
비용도 호가 WS 미구독이라 슬리피지가 설정값 근사다(시장충격만 완성봉 volume으로 정확).

## 3.4 Risk Engine 거부권

검사 순서: **Net ER ≤ 0** → R11 데이터단절(30초) → R13 CB → R10 연속손실(입력 없음) →
R12 주문오류 → R2 일일손실 → R6 오버나이트 자격 → R4/R3 증거금 → R5 포지션 수.

08-21은 **첫 번째 검사에서 종결**됐다. 나머지 8개는 여전히 라이브 미검증이다.
R1은 여기가 아니라 Sizer의 사이징 상한으로 강제된다(구조적 보장).

## 3.5 ★ Position Sizer — 진짜 벽은 여기다

```
vol_target_qty = equity × 2% / (ATR틱 × tick_size × point_value)
qty            = floor( vol_target_qty × edge × 0.25 × (1 − uncertainty) )
```

08-21 값(equity 5,000만 · tick 0.02 · point_value 50,000 · ATR 48.93 · u 0.0442):

```
vol_target_qty = 20.44
qty            = floor( 4.884 × edge )        →  1계약에 필요한 edge = 0.2048
                                              →  필요 confidence   = 0.6024
Net ER > 0에 필요한 edge = 비용/ATR = 0.0332  →  필요 confidence   = 0.5166
```

**두 벽이 ATR에 대해 반대로 움직인다.** ATR이 커지면 Net ER 문턱은 낮아지고(움직임이 크니
비용을 넘기 쉽다) 사이징 문턱은 높아진다(계약당 손실이 커져 수량이 줄어든다). 교차점은
`ATR = √(비용/k) ≈ 19.7틱`이고, 그 지점에서 필요 confidence가 최소가 된다:

| ATR(틱) | Net ER 문턱(edge) | 사이징 문턱(edge) | 구속하는 쪽 | 필요 confidence |
|---|---|---|---|---|
| 10 | 0.1623 | 0.0419 | Risk | 0.581 |
| **19.7** | 0.0824 | 0.0824 | 교차 | **0.541 ← 최소** |
| 30 | 0.0541 | 0.1256 | Sizer | 0.563 |
| 48.93 (08-21) | 0.0332 | **0.2048** | **Sizer** | **0.602** |
| 80 | 0.0203 | 0.3348 | Sizer | 0.667 |

> **결론: 현재 설정에서 어떤 ATR에서도 `confidence ≥ 0.541` 아래로는 1계약도 나오지
> 않는다.** confidence는 선택된 방향의 가중평균 확률이므로, 이는 **한 클래스 확률이 54%
> 이상**이어야 한다는 뜻이다 — flat 76.3%로 학습된 30m 모델에는 매우 높은 요구다
> (08-21 최고치 0.4873).

이 산술은 08-16판에도, 08-21 일일 리포트에도 없다 — **이번 조사에서 처음 계량됐다.**
`edge = 2p − 1`은 대칭 페이오프(b=1) 가정의 근사이고 `point_value 50,000`은 실측 전
placeholder이므로, **둘 중 하나만 바뀌어도 이 벽의 높이가 바뀐다.**

## 3.6 Order Gateway

```
submit(req):  1) pending 원자 등록(전송 전) → 2) broker.submit() → 3) 실패 시 롤백·None
on_fill():    매칭 실패 → FillUnmatched CRITICAL + 즉시 halt (유령 포지션을 만들지 않는다)
```

주문 경로는 이것 하나뿐이고 우회 신설이 금지돼 있다(계명 1 / L1). `halted`에서도
`kind=EMERGENCY`는 통과한다. **아직 한 번도 도달한 적 없다** — `accepted_orders = 0`.

## 5.2 진입이 실제로 나지 않는 이유 (2026-08-23 재정렬)

1. **★ `edge = 2·confidence − 1` 벽 — 새 1순위.** confidence가 0.5를 못 넘으면 Net ER이
   항상 −(비용)이고, 1계약이 나오려면 어떤 ATR에서도 **0.541 이상**이 필요하다(§3.5).
   08-21 최고치 0.4873. **Risk와 Sizer가 같은 근사를 쓰기 때문에 벽이 두 겹**이다. 이
   근사는 실현 거래 통계가 없어 도입된 임시 공식이므로, 고칠 자리가 **모델이 아니라 공식일
   수도 있다** — 판단하려면 4번(Position Reconciler)이 먼저다.
2. **레이블이 flat 쪽으로 쏠려 confidence를 구조적으로 낮게 만든다**(§2.6). "불가능"은
   아니지만 평균적으로 매우 불리하다. 비용 강등 규칙 0건 · 배리어 폭 재검토는 유효하며,
   **왕복 비용 실측이 선행**이다.
3. **국면 의존 — RANGE 구간에는 30m 단독으로 게이트를 못 넘는다**(§2.4). Horizon을 하나
   더 여는 것(15m·10m)이 국면 의존을 낮추는 직접적인 처방이다.
4. **메타 게이트가 무력화된 채로 돌고 있다**(§2.3). 지금은 하류가 막고 있어 결과가
   같지만, 1·2번이 풀리는 순간 **검증되지 않은 상태로 열린 차단 계층 하나가 그대로
   실거래 경로에 남는다.** F-6 처방 필요.
5. **`live` 번들이 30m 하나, 성과 관문 셋 미측정**(§2.2). `logs/g1_walk_forward_20260804.json`
   의 `cost_adjusted_sharpe 0.0 · passed: false`가 아직 유효한 마지막 성과 기록이다.
6. **Position Reconciler 부재** → R10 입력 없음 · 실현손익 매칭 불가 · Kelly `edge` 교체
   근거 없음 · Cost Model 자기보정 불가. **1번의 해결 가능성이 여기에 걸려 있다.**
7. **정보 폭 부족** — MS/OP/RG 전무, Horizon별 피처 배정 미구현. 위가 다 풀려도 판단
   재료는 설계의 1/3이다.
