## Fix 작업 구현계획 — 장전

### F-1. 저장소 잠금 파일(`index.lock`) 정리 — P1 · 대응 이상점 1-1

- **원인 가설**: 이 점검 세션이 저장소 상태 확인을 위해 `git status --porcelain`·`git diff`를 직접 실행했고(F-78/F-112 위반), 이 세션이 쓰는 실행 환경(원격 사용자 파일 마운트)에서는 그 결과로 생긴 `.git/index.lock`을 세션 스스로 지울 권한이 없다(다른 접근 방식으로 지우려는 시도 3가지 — `rm`, 파이썬 `os.remove`, `chattr` 확인 — 전부 "Operation not permitted"로 실패).
- **변경 파일**: 없음(코드 변경이 아니라 잔존 파일 삭제 1건).
- **조치 내용**: 사용자가 자신의 컴퓨터(Windows, 원격 세션이 아닌 실제 PC)에서 다음 중 하나를 실행한다.
  1. 파일 탐색기에서 `C:\Users\82108\PycharmProjects\fuoption\.git\index.lock` 파일을 직접 삭제(숨김 폴더이므로 `.git` 폴더가 안 보이면 탐색기 "숨김 항목 표시"를 켠다).
  2. 또는 파워쉘에서 `Remove-Item "C:\Users\82108\PycharmProjects\fuoption\.git\index.lock"` 실행.
  3. 또는 이 저장소에 이미 있는 안전장치를 그대로 쓴다 — 파워쉘에서 `cd C:\Users\82108\PycharmProjects\fuoption; python scripts\git_lock_guard.py --check` 로 먼저 "스테일 확정"인지 확인한 뒤 `python scripts\git_lock_guard.py --reclaim` 실행(이 스크립트는 파일 크기가 0바이트·생성 후 10분 이상 경과·실행 중인 git 프로세스 없음 세 조건을 전부 다시 확인한 뒤에만 지운다 — 살아 있는 git을 잘못 지우는 사고를 막기 위한 장치).
- **회귀 위험**: 없음. 이 락은 아무 git 작업도 진행 중이 아닌 상태에서 생긴 0바이트 잔존 파일이므로, 지워도 저장소 내용에는 아무 영향이 없다(위 세 조건이 이미 "진행 중인 작업 없음"을 보장한다).
- **검증 방법**: 삭제 후 아무 디렉터리에서나 `git status` 실행 — 오류 없이 평소처럼 결과가 나오면 해소 확인.
- **적용 시점**: 즉시 가능 — 코드 변경이 아니라 잔존 파일 삭제이므로 SYSTEM.md R11(장중 코드 배포 금지)이 적용될 대상이 아니다. 다만 늦어도 오늘 저녁 하루 기록 저장 작업 전까지는 반드시 처리해야 한다.
- **결정 필요 사항**: 없음.
